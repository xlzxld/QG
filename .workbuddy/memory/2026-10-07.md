## ★ 用户澄清：主场景是「手动打开的别的商品页」

我第一轮理解偏了——只堵了"槽位派发"那条路。用户说的是**他自己用浏览器逛
其他商品页时，脚本不应该有任何动作**。油猴脚本 `@match` 覆盖全站商品页
（`item.vmall.com/product/comdetail/*`、`www.vmall.com/product/*`、
`m.vmall.com/product/comdetail/*`），所以他随便点个商品页脚本都会注入。

### 查出的两个真漏洞

**漏洞 1：闸门装得太晚（在副作用之后）**
原 main() 顺序是「插面板 → loadConfig（GET 桥接 + `GM_setValue('config')`
**覆写全局配置缓存**）→ flushPending 补发历史 → 才 checkTarget」。
也就是说在不在列表的商品页上，脚本照样插面板、照样发请求、照样覆写缓存。
真正点击购买被守着（checkTarget 之后），但"运作"本身已越界。

**漏洞 2（更隐蔽）：SPA 切页不重载文档**
vmall 是 Next.js 单页应用，站内点推荐位跳转只换 URL 和 DOM，
**油猴脚本不重启** → `checkTarget` 只在启动时跑一次 →
用户从列表内商品点进别的商品，脚本会**继续盯着新商品抢**，
而且绑的还是**上一个商品的规格和价格上限**（等于拿错刀）。

### 改法（huawei.user.js，三层）

| 层 | 时机 | 行为 |
|---|---|---|
| 第 0 道 启动闸 | 一切副作用之前 | 只读 GM 缓存判定；不在列表 → **连面板都不插、请求不发、缓存不写**，只 console.info |
| 第 1 道 配置复核 | loadConfig 之后 | 列表刷新后本页变列表外 → `teardownPanel()` + 回传 SKIPPED_NOT_TARGET |
| 第 2 道 切页哨兵 | `main()` 一进去就装 | 监听 pushState/replaceState/popstate + 500ms 轮询兜底 |

配套新增：`state.silent`（静默模式，ensurePanel 一律返回 null）、
`teardownPanel()`、`stillOnTarget()`、`watchTargetLeaving()`、`state.targetPrdId`。

`stillOnTarget` 比对基准是**启动时匹配到的 prdId**，不是"列表里任意商品"——
否则 A 商品页启动、切到也在列表里的 B 商品会判定通过，而绑的还是 A 的规格。

### ⚠ 踩坑：哨兵最初装在「匹配到目标」之后 = 形同虚设

第一版把 `watchTargetLeaving(config)` 放在 `checkTarget` 匹配成功之后，
实测 SPA 闸门**失败**（跳后面板仍在）。加探针查 console 发现只打到
「脚本已注入，正在载入配置…」就断了——脚本卡在 `loadConfig()`
（等桥接响应），永远走不到装哨兵那行。
→ **哨兵这类"防御性监听"必须装在所有前置判定之前**，不能依赖主流程走完。

修完实测由 `路由跳转` 触发（即时），不是等 500ms 轮询兜底。

### ⚠ 踩坑：闸门测试第一版测了个寂寞

`window.__gm = {}`（**空缓存**）→ 脚本在列表内页面也是因为"无缓存"提前退出的，

#### ⚠ 踩坑：停止失败却报成功

第一版用 `execSync('netstat ...')` + `taskkill` 找端口杀进程。**本工具环境里
从 Node 起任何外部进程都 EBUSY**（netstat / taskkill / cmd 全部 spawnSync 失败），
异常被 catch 吞掉 → 返回 null → 于是"停止失败"却打印了"重启成功"（最糟的情况：用户
以为跑的是新代码，其实是旧的）。
→ 改成 PID 文件 + `process.kill`（零依赖，实测可用）；外部命令只作兜底，
且**任何一步没成功都不许报成功**。

### 二、油猴脚本误报"未登录"（用户明明登录着）

**根因**：会话 Cookie `sid`/`hwid_cas_sid` 在 `.id1.cloud.huawei.com` 域下，
脚本跑在 `item.vmall.com` 上，**跨站读 Cookie 被限制 → GM_cookie 返回空数组**。
第一版把"空"当成"没有凭据 = 未登录" → 误报。
（教训：**"看不到" ≠ "不存在"**，跨域读空只能算未知。）

**修法 —— 换成真正的响应判据（这是正解）**：
在会员页抓到页面自己判断登录态的接口：

```
GET https://openapi.vmall.com/mcp/queryUserInfo?portal=1&lang=zh_CN&country=CN
已登录 → {"code":"0","success":true,"userInfo":{"authCust":true,"custGrad":3,"nickName":"Always","uid":"...","userAccount":"..."}}
未登录 → {"data":"user not login.","info":"用户未登录","resultCode":"200916"}
```
`custGrad=3` 正好对应会员页的"V3 等级" —— 确认就是它。
在商品页用**页面自己的 fetch**（`credentials:'include'`）调用即可，
浏览器自动带 Cookie，**不受跨站读取限制**。

判据优先级（三层，页面文案降到最后）：
① 页面自己流量里的"登录已过期"硬信号（60 秒保鲜期）→ 未登录
② `queryUserInfo` 响应（主判据，带 5 秒缓存）→ 已登录/未登录
③ 本地可见的会话 Cookie（跨站通常看不到）→ 已登录
④ 页面登录标记（最后兜底，等水合 + 多拍；判不出记 unknown，**不拦不猜**）

#### ⚠ 测试侧又踩三个坑

1. **CORS**：跨域带凭据的请求不能用 `Access-Control-Allow-Origin: *`，

### ★ 关键钥匙：`userGesture:true`（第一版"没走通"的真凶）

### 关键技术手法（可复用）

- **闭包变量读取**：闭包变量无法从页面 JS 访问，用 CDP `[[Scopes]]` 通道：
  `evaluate(returnByValue:false拿onPress) → getProperties × N → Closure scopes → 目标变量`
  ——全链 ~5ms，**无副作用**（不执行函数），比断点法干净。
  - ⚠ 同名变量跨 scope 串台：必须"只认定义了 `Yo` 的那个 Closure"（组件闭包 Ct）。
- **现取现调**：每轮从 DOM 重取 fiber 闭包（不缓存）→ 天然抵抗 React 重渲染，
  永远拿到最新按钮状态（文案 qo / buttonMode 快照）。
- **未开售 fire 零副作用**（实测页面毫无变化）→ 可以热窗内高频调 Yo，无后顾之忧。
