# 加一个新平台

这份文档回答一个问题：**以后加别的网站（秀动、大麦、京东…），会不会乱套？**

答案：不会。前提是按下面这层约定来写新爬虫。

> **2026-10-08 结构重组更新**：本文路径已同步到新结构（`core/ platforms/ web/ tools/ verify/ docs/`）。
> 控制台形态已演化为「工作台外壳 + 平台专属页」：新平台页面放 `web/platforms/` 并在 `data/grab/manifest.json` 登记。
> 已知遗留：桥接的体检驱动注册表仍写死（加平台体检要改 `core/grab-bridge.mjs` 的 CHECKUP_DRIVERS），待秀动开发时一并数据化。

## 一、现在的分工

```
┌─────────────────────────────────────────────────────┐
│  控制台 grab-console.html          ← 通用，不用改    │
│  （只认"统一字段"，不知道有华为这回事）               │
└───────────────────────┬─────────────────────────────┘
                        │ /api/xxx/<平台>
┌───────────────────────┴─────────────────────────────┐
│  桥接服务 grab-bridge.mjs          ← 通用，不用改    │
│  （配置、结果、调度全部按 <平台>.config.json 区分）  │
└───────────────────────┬─────────────────────────────┘
                        │ 读 / 写
        ┌───────────────┼───────────────┐
        ↓               ↓               ↓
   crawler-huawei   crawler-新平台A   crawler-新平台B
   （平台专属，要写）  （平台专属，要写）  （平台专属，要写）
        +
   huawei.user.js   新平台A.user.js   新平台B.user.js
   （平台专属，要写）  （平台专属，要写）  （平台专属，要写）
```

**通用层已经抽好了。** 平台专属的东西全部收敛在"爬虫 + 油猴脚本"这一对文件里。

## 二、加平台要写的三个文件

以"秀动"（示例）为例：

### 文件 1：`platforms/showstart/crawler-showstart.mjs`

照 `crawler-huawei.mjs` 的结构写。核心是三件事：

**① 只去配置里的 URL**，不自己发现别的商品。

**② 把每个"可选规格"输出成统一字段**（见下节表格）。

**③ 输出平台元信息**：

```js
platformMeta: {
  key: 'showstart',
  label: '秀动',
  skuIdLabel: '票档编号',
  specLabel: '票档',
  addUrlPlaceholder: 'https://www.showstart.com/event/xxxxx',
  orderLookupHint: '在秀动 App「我的订单」里核对',
}
```

写入 `data/grab/showstart.catalog.json`。

### 文件 2：`platforms/showstart/showstart.user.js`

照 `huawei.user.js` 写。要做的事一样：

1. 从桥接服务读配置
2. 用 **prdId 或 URL** 匹配当前页面是配置里的哪个商品（别用标题关键字）
3. 切到配置里勾选的规格（`skuIds`）
4. 到点检测"可购买"状态并点击
5. 读页面上的真实订单号回报（读不到就报"结果未知"，**不要编**）

### 文件 3：注册到 `data/grab/crawlers.json`

```json
{
  "id": 2,
  "name": "秀动",
  "platform": "showstart",
  "script": "platforms/showstart/crawler-showstart.mjs",
  "enabled": true,
  "presetArgs": [
    { "key": "1", "label": "完整采集", "args": [] }
  ],
  "desc": "采集演出票档与开售时间",
  "schedule": false
}
```

改完保存，**控制台会自动出现这个平台**，启动器菜单里也会多一项。

## 三、统一字段约定（关键就这一张表）

爬虫输出的每个"可选规格"，除了平台自己的原始字段，**必须**再输出这组：

| 字段 | 含义 | 华为是怎么映射的 |
|---|---|---|
| `skuId` | 该平台用来唯一标识这个规格的编号 | `sbomCode` |
| `label` | 完整名称 | 页面给的 `name` |
| `attrs` | 属性维度（键值对） | `{颜色, 版本, CPU型号}` |
| `price` | 价格（数字） | `price` |
| `statusText` | 状态人话 | `"抢购未开售" / "现货可买" / "缺货"` |
| `buyable` | 现在能不能直接买（布尔） | `buttonMode === 1` |
| `saleStartAt` | 开售时间（ISO 带时区） | `rushBuy.startTime` |
| `limitPerUser` | 每人限购 | `rushBuy.limitNum` |
| `stockQty` | 库存数（`null` = 查不到） | `inventoryQty` |
| `stockCapped` | 库存是不是"充足"的封顶值 | `inventoryCapped` |

再加一个 `specDimensions`（规格维度，用于面板上的快捷筛选）：

```js
specDimensions: [
  { name: '颜色', values: [{ value: '曜石黑', skuIds: ['2601...'] }, ...] },
  { name: '版本', values: [...] }
]
```

**只要输出这些，控制台一行都不用改。**

平台自己的字段（比如华为的 `buttonMode`、`rushBuy`）**照样保留**，方便排查问题。

## 四、配置格式（所有平台一样）

```jsonc
{
  "platform": "showstart",
  "products": [
    {
      "id": "某场演出",
      "enabled": true,
      "url": "https://www.showstart.com/event/xxxxx",
      "skuIds": ["票档编号1", "票档编号2"],  // 空 = 全部
      "maxPrice": 880,
      "quantity": 1,
      "saleAt": "2026-10-08T12:00:00+08:00"
    }
  ]
}
```

放在 `data/grab/showstart.config.json`。

## 五、不用改的东西（清单）

| 东西 | 为什么不用改 |
|---|---|
| `web/platforms/` 的平台页面 | 架构＝工作台外壳 + 平台专属页；统一字段渲染与 `platformMeta` 文案位可直接沿用 |
| `core/grab-bridge.mjs` | 全部接口都是 `/api/xxx/<平台>` 形式，天然多平台 |
| `启动.bat` | 菜单从 `crawlers.json` 动态生成 |
| 配置结构 | `products[] / skuIds / maxPrice / quantity / saleAt` 是跨平台约定的 |
| 结果回传格式 | `outcome / platformOrderNo / message` 也是约定的 |

## 六、加平台时真正需要留意的三件事

**1. 编号字段名可能不叫 sbomCode**
秀动可能是 `ticketId`，京东可能是 `skuId`。写爬虫时映射到统一的 `skuId` 就行。

**2. "属性维度"可能不是颜色/版本**
演出是"场次 + 票档"，机票是"舱位 + 日期"。`attrs` 是键值对，随便什么维度都能装。

**3. 开售时间的来源不同**
华为要从接口旁听拿（页面首屏没有）。别的平台可能页面里就有，也可能要点击才出。
**只要最后填进 `saleStartAt` 就行**，来源无所谓。

## 七、如果两个平台要同时抢

控制台是分开的页面（`?platform=xxx`），但**桥接服务是同一个**，调度也是同一个。

多平台同时抢时，注意：

- 每个平台的爬虫各自独立，互不干扰
- 油猴脚本按 `@match` 只在自己平台的页面上跑，不会串
- 结果回传按平台分开存（`<平台>.results.jsonl`）

如果要在**同一时刻**抢不同平台的东西，那就是多账号并发那个问题，
见 `多账号并发方案.md`。
