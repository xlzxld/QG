## 3. 最终技术裁决

### 3.1 技术栈定格

```
Node 控制台（现有 grab-bridge :3100 + 新增 device-hub :3120）
  + ADB（adb reverse 通道 / 设备管理 / 冷启兜底）
  + AutoX.js v7（aiselp/AutoX，固定 v7.2.4）＝ 手机端正式执行引擎
  + uiautomator2 ＝ 标定/侦察仪器（不进生产热路径）
  + QtScrcpy ＝ 监控墙 + 群控人工接管
  + Shizuku ＝ 无障碍自愈与 shell 兜底
  + Android 真机 ＝ 唯一实弹环境
```

对整合稿「冻结规则」的修正采纳：**冻结时点不在今天，而在 Phase 0 冲刺验证通过之后**（见 §8），验证项 = v7 在目标真机上的三个硬前提：intent 启动组件实测、存储权限、Shizuku 无障碍自愈。三项任一失败 → 启用 AutoJs6（MPL-2.0，V4）做同一 Agent 代码的移植评估（两者选择器 API 同源，脚本主体可移植）。验证通过 → 冻结，后续不再推倒引擎选型。

**关于「一套引擎」**：整合稿说「不要再维护两套 Android 主引擎」，正确；但要补一句——**uiautomator2 不是第二套引擎，是仪器**。它的角色：标定期的元素侦察（配合 uiauto.dev，weditor 已死）、8 项标定里的「无障碍覆盖率表」测绘、页面改版后的诊断探针。生产热路径只有 AutoX.js v7 一个引擎。

### 3.2 对方案三 U1-U3 三项待拍板的裁决

| 待拍板 | 裁决 | 理由 |
|---|---|---|
| U1 端侧引擎 | **AutoX.js v7（aiselp，GPL-2.0）**，AutoJs6 备胎 | v7 本轮实证活跃（v7.2.4 十天前发版）；项目定位非商业研究，GPL-2.0 无碍（§7.4）；Shizuku + Node 引擎是差异化能力。AutoJs6 星数更高、MPL 更宽松，作为冻结失败的 Plan B |
| U2 平台解锁顺序 | **大麦 → 京东 → 淘宝**；猫眼/纷玩岛作顺风车 | 与方案三（京东优先）不同：v3 渠道表大麦是 S+ 核心、价值最高；其 UI 流程确定性最强（详情→选场次票档→确认→提交），且 Pactum7 的猫眼实现验证了同类流程在 AutoX.js 上跑得通（模式可直接迁移）。京东标定成本最低，作第二战线并行推进；淘宝混淆 ID 最难，最后 |
| U3 全自动门槛 | **采纳方案三原案**：标定 8 项全过 + 两轮彩排（模式乙→模式甲）+ 负样本全部判对 | 无增量异议；负样本判对是「不误报成功」的唯一直接证据 |

## 5. 关键机制设计

### 5.1 通讯与调度（通道：adb reverse + HTTP 长轮询）

方案三的论证完整（零新端口/零新依赖/USB 内跑/断线重连简单），WebSocket 与 MQTT 维持否决：击发不依赖实时推送，P0 引入实时总线只增加活动件。补充两点：

- **心跳哨兵在 device-hub**：`adb reverse` 易失（拔线/adb 重启即丢），哨兵发现「adb 在线但通道探测失败」自动幂等重发 reverse。
- **device-hub 独立进程**（沿用我上轮 D2 决策）：桥接铁律是改 `core/` 必重启，若 device-hub 长在桥接里，重启即解除全部已布防设备。

### 5.2 时间系统（毫秒级成败所在，融合三家长处）

1. **权威钟 = 平台服务器**（方案三 A1 裁定），PC 与手机都只是本地钟。NTP 仅作交叉校验。
2. **采样 = min-RTT 法**：连采 5-10 次取最小往返样本的 offset（我上轮与方案三一致；方案二的「取中位数」已被方案三审查正确否决）。
3. **末段死等 = 单调钟**：最后几十毫秒用 `System.nanoTime()` 级单调计时，禁止墙钟（防系统校时跳变，方案三抓出的要点）。
4. **相对标定法兜底**（方案三原创，采纳）：无公开对时接口的平台（淘宝/大麦），不硬测绝对时刻，改为演练期「扫描平台接受点击的最佳提前量」直接得 `leadMs`。
5. **京东对时源 = 标定项**（V5）：候选三路——`api.m.jd.com` H5 接口时间戳（functionId 以实测为准）、响应 Date 头 + NTP 插值、相对标定法。开售前 1 分钟必复采。
6. **标定产物入库**（整合稿的表结构，采纳）：`platform / measure_time / offset_p50 / p95 / p99 / lead_ms / sample_count`，每场复盘修正。**不承认任何「通用提前量常数」**。

### 5.3 一键拉起（10 步链 + 8 项标定 + 双模式）

拉起链、8 项标定清单、双模式（模式乙「人工就位 + 脚本击发」为 P0 一等公民）全部沿用方案三设计（其审查与独立评审已把断点逐条打过补丁）。叠加我上轮的三级拉起分级与两点纪律：

- **冷启动一律 `monkey -p <包名>`**（方案二给的 `am start -n` 组件名未核实、京东那组包名前缀可疑，V7）；deeplink 到达按 V6/V8 状态分平台维护，**失效自动降级冷启 + u2/AutoX 导航，不阻塞平台**。
- **大麦 deeplink 未核实前不进任何预案**（我上轮 D4 决策维持）：阶段 0 用 `aapt2 dump badging` 反解 APK + logcat 抓路由，产出 `platforms/app/deeplinks.json` 后才解锁。

### 5.4 平台 Adapter（整合稿接口 + 方案二战术）

统一接口（冻结）：`prepare / preflight / prime / fire / readResult / recover`。状态驱动，每步有成功判据；页面身份不符/票档不存在/结构大变 → 立即停手、截图、告警、`WAITING_HUMAN`，禁止未知页面盲点。

| 平台 | 战术要点（来源标注） |
|---|---|
| 大麦 | 提前录入全部观演人；开售前 3 分钟详情页展开选票面板预选场次+票档；**不读倒计时文本**，按校准本地时到点高频点右下角按钮；确认订单页第一瞬间按观演人姓名勾选 CheckBox 后立即提交；滑块 → 蜂鸣 + QtScrcpy 置顶人工 1 秒划掉（方案二，全部采纳） |
| 京东 | 预约资格前置巡检（T-30 检查「已预约」态）；BP 直达链 `p.m.jd.com/norder/order.action?wareId=…&enterOrder=true`（社区实证，标定复测）；支持直购的商品跳过购物车直达结算（方案二+三） |
| 淘宝 | 双模式：可加购商品走**购物车合并结算**（T-1 勾选、监听结算栏、到点前 50ms 起高频检查按钮态）；不可加购走详情页立即购买；resource-id 混淆 → 文本/desc/坐标三级降级树（方案二，采纳） |
| 猫眼/纷玩岛（顺风车，可选） | Pactum7 Apache-2.0 脚本可直接跑在 AutoX.js 上：卡点抢票 + 余票监控 + webhook。作为 P0a 监控期的第一批真实验证载体，顺带验证 v7 引擎兼容性。**明示：这是 v3 渠道表外的增量，不占核心资源** |

### 5.5 幂等与结果（方案三原案，全盘采纳）

- 端侧 outbox（先落盘后上报，断线重传）；桥接 `taskId+seq` 去重；端侧「已击发」标记拒绝二次击发；过期任务作废。
- 结果枚举五值 `ordered/no_stock/risk_challenge/unknown/failed`；**`ordered` 只认凭证**（订单号或「我的订单」可查），文案信号仅辅助；不确定 → `unknown` + 人工，不自动重试。
- 击发纪律（铁律级）：**窗口期只发一发、绝不重试**；非窗口期监控 10-30s 低频 + 退避。

### 5.6 风控与行为纪律（真机≠免疫）

模拟器边界四方案已一致（开发/彩排可用、实弹禁用、登录/实名/下单绝不上模拟器），不再重复。真机侧纪律（方案三 §5.2 + 我上轮 F5/F6 合并）：

- 一机一账号，会话隔离，不做高频账号切换；
- MotionEvent 注入特征已被风控研究文档化（网易易盾等）——**无任何方案承诺存活率**，小号灰度先行；
- 多机同毫秒击发是行为聚集信号：抖动窗口 ±0~80ms 可配置（大麦实名场建议开）；
- 可选：旧真机做**检测靶机**，先摸清平台在意哪些项再定细节；
- 账号质量 > 工具（社区一致结论），养号与账号隔离纳入运维规范。

## 7. 安全、许可证与合规

1. **GPL-2.0 边界**（整合稿结论修正后采纳）：AutoX.js v7 为 GPL-2.0，本项目定位个人非商业研究、不分发衍生物 → 当前无触发；**业务脚本与运行时保持目录/依赖边界**，不复制其内部实现。未来若商业化或分发打包 APK → 重审，Plan B = AutoJs6（MPL-2.0）。
2. **引擎版本锁定**：AutoX.js 固定 v7.2.4 APK 留存于本地版本库，禁自动更新；脚本只用稳定 API 子集（选择器/HTTP/文件/线程/计时），防引擎换代伤筋动骨。
3. **数据安全**：观演人姓名/身份证只落 `data/grab/`（确认 `.gitignore` 覆盖），日志不打印证件号。
4. **边界**：桥接与 device-hub 均只监听 127.0.0.1；`adb reverse` 把访问天然限制在设备对之间；局域网多机模式是 P2 且必须先加设备令牌 + IP 白名单 + 收掉 `Access-Control-Allow-Origin: *` 遗留。
5. **红线**（四方案一致）：不破解滑块、不协议直刷/抓包重放（法律判例 + 铁律 + 风控三重否决）、验证码一律转人工、止步支付页演练、实名票不囤不倒。
